# GRANTLY outcome checklist

## 1. Sample data, matching, dates, and persisted state
- [x] **Core scholarship and match foundation:** Use Scholarship `{id, name, provider, amount, currency:'USD', deadline:'YYYY-MM-DD', level:[], fields:[] ('Any' = all), countries:[] ('Any' = all), minGpa (0 = none, 4.0 scale), maxIncome (1 low, 2 middle, 3 high = no limit), categories:[] (required category, empty = none), requiredDocs:[], description}` and Profile `{name, level, field, country, gpa, income (1|2|3), categories:[]}` data. Supply 16 scholarships with fictional names/providers, amounts from $3,500 to $42,000, varied levels/fields/countries/GPA/income/categories, one already-passed deadline, and some due within 2 to 10 days; generate all deadlines relative to today and label the dataset “Sample data for demonstration”. Preload Student, Undergraduate, Computer Science, India, GPA 3.4, Middle income, no categories.
- [x] **Explainable weighted matching:** `evaluate(scholarship, profile)` returns `{score:0..100, eligible:boolean, criteria:[{key,label,detail,status:'met'|'partial'|'unmet',weight}]}`. Weights: field 30, level 20, country 20, GPA 15, income 10, category 5; met=1, partial=.5, unmet=0. Field/level/country match “Any” or the profile value; GPA is met at/above minimum, partial within 0.3 below, otherwise unmet; income is met when there is no limit or profile income is at/below the maximum; category is met with no requirement or any overlap. Eligibility is true only when no criterion is unmet. Every criterion has a human-readable explanation. Call this a rule-based Smart Match, not AI, and do not show fabricated marketing numbers.
- [x] **Safe local state:** Context + `useReducer` actions `SET_PROFILE`, `TOGGLE_SAVE`, `SET_STAGE`, `SET_NOTES`, `REMOVE_APP`, `TOGGLE_DOC`, `RESET_ALL`; persist `{profile,applications,documents}` at `grantly:v1`; safely load and merge defaults so corrupt storage does not crash the app. Memoize match results by profile and expose a toast helper; toast announcements use `aria-live="polite"`.
- [x] **Date and format helpers:** `today`, `addDays`, `daysLeft` using `Math.round` for DST safety, `urgencyOf` (closed/urgent <=7d/soon <=21d/open), and `formatDate`; parse YYYY-MM-DD as a local date, not UTC. Format currency with `Intl` and no decimals.

## 3. Scholarship discovery and detail drawer
- [x] **Discover tools:** Search name/provider/description; filters for level, field, country, Eligible only, deadline Any/7 days/30 days; sorting Best match, Deadline soonest, Amount high to low. Read `q` and `eligible=1` from URL. Show result count, Clear filters, and a proper empty state. On mobile filters use a bottom sheet opened by a Filters button.
- [x] **Results and detail:** Cards show name, provider, amount, deadline badge with days left and urgency conveyed by text plus icon (not color alone), match percentage ring, Eligible/Not eligible, Save/Saved, and View details. Drawer is right-side on desktop/bottom-sheet on mobile; includes description, amount, deadline, explainable eligibility breakdown with check/half/cross icons and detail, required documents with global ready/missing status, Save/Unsave, and Start application (creates/moves to Drafting and toasts). Closed scholarships show Closed and cannot be started. Esc closes, focus is trapped and restored, and background scroll is locked while open.

## 4. Tracker, calendar, and documents
- [x] **Tracker:** Kanban with all six stages (Saved, Drafting, Submitted, Interview, Awarded, Rejected). Each application card shows name, amount, deadline badge, match %, a stage `<select>` (primary stage movement, usable on touch), notes textarea (saved on blur or debounce), and Remove. Each column header shows count and total amount. Empty state links to `/discover`. Mobile columns horizontally scroll with snap. Desktop drag-and-drop is optional.
- [x] **Calendar:** Month grid with previous/next/Today buttons; deadline dots use urgency colors and tracked items are emphasized. Clicking a day lists deadlines; clicking an item opens detail drawer. Add “Due in the next 14 days” side list and All scholarships/My tracked only toggle. Day buttons are keyboard navigable and have aria-labels; Monday-first or Sunday-first is acceptable.
- [x] **Documents:** Aggregate unique required documents across tracked scholarships; each has a ready/not-ready toggle and lists scholarships that need it. Each tracked scholarship shows docs-ready/docs-required progress; show a Ready to submit highlight at 100%, and an empty state when nothing is tracked.

## 5. Profile, accessibility, responsiveness, and delivery
- [x] **Profile:** Editable name, level, field, country, GPA from 0 to 4.0 with validation, income, and category checkboxes. Save live; show “Your matches updated: N eligible scholarships”. “Reset demo data” has a confirmation dialog and runs `RESET_ALL`.
- [ ] **Accessibility and responsive behavior:** Semantic header/nav/main/footer landmarks; one h1 per page; visible focus rings; labelled controls; aria-labels for icon-only buttons; never convey status by color alone; focus-trapped modal/drawer with Esc support. Honor `prefers-reduced-motion`. Work at 360px, 768px, and 1440px with no horizontal page scroll; keyboard-only use is possible.
- [ ] **Functional delivery:** Refresh retains profile, saved items, stages, and document toggles. Profile changes update scores and eligible filtering. Every button/link/nav item works; search, all filters and sorts work and empty state appears. Drawer opens from Discover, Calendar, and Home; Esc closes. Start application moves an item to Drafting and updates Tracker, Home stats and Documents. Past deadline is Closed and deadlines within 7 days are urgent. Direct `/tracker` visit works on Vercel. Build passes with `npm run build`; provide a manual test checklist and Vercel deploy steps (`npm run build`, then `npx vercel` or GitHub import), and list anything not verified.
